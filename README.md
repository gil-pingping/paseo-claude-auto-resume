# Paseo Claude and Codex auto resume

Resume a Claude Code or Codex agent in Paseo after its usage limit resets. The plugin watches for the provider's limit response, waits until one minute after the stated reset time, then sends a new continuation turn to the **same agent**. It cancels the pending turn if you resume manually or archive the agent.

This version handles Claude reset messages labelled `Asia/Seoul` and Codex `try again at` messages interpreted as Seoul time, both within six hours. It sends a Korean continuation prompt. It does not replay the interrupted turn or its attachments. The plugin ID and repository name retain `claude` for existing installations.

## Install

Requires Paseo 0.11.1 or newer, an available Claude or Codex provider, and plugins enabled on the daemon host. Plugins run trusted code on that host; review the source before installing.

```bash
paseo plugin add git:gil-pingping/paseo-claude-auto-resume
paseo plugin ls claude-auto-resume
```

`running` means the hook is active. It handles new limit events from installation onward. The plugin logs `Scheduled Claude agent after usage reset` and `Resumed Claude agent after usage reset` without storing conversation text.

```bash
paseo plugin logs claude-auto-resume
```

To stop it, run `paseo plugin disable claude-auto-resume`.

## Limits

- Paseo daemon and plugin must remain running until reset. Plugin reload or daemon restart loses pending timers.
- Only top-level Claude and Codex agents are resumed. Each reset triggers at most one follow-up. A manual turn cancels a pending follow-up.
- Claude's reset clock must be labelled `Asia/Seoul`. Codex's timezone-free clock is interpreted as Seoul time. Other time zones are unsupported.
- Real account limits cannot be generated by the test suite. Tests use synthetic limit events. One live Claude reset on Paseo 0.11.1 was observed on 2026-10-09: the plugin sent the follow-up at the reset time and the agent continued working. Codex's new path has no live reset verification yet.
